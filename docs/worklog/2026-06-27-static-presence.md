# 静止在室検知（object_raw 併用＋適応ベースライン）— 2026-06-27

## 0. 一行まとめ

1m 先に静止して座っていると在室判定が消える問題を、**生サーモパイル `object_raw` を在室判定に併用**して解決。製品の presence アルゴリズムが「静止した体」を背景吸収してしまう構造的弱点を、`object_raw` の「適応ベースラインからの超過」で補う。当初の「在室中ベースライン凍結」案は 9.7 日ログの replay で**2.6 日連続ラッチ**を起こしたため、**非対称 EMA 常時追従**へ設計変更。実機 E2E green（9 分静止で active 維持・離脱で即 disarm・誤ラッチ 0）。

> 注: 同日 11:59 の `2026-06-27-presence-calibration.md` は「センサーはベッド向き・仕事スペースは無視」を前提にしていたが、本作業時点ではセンサーがリビング側を向くよう再設置済み（ユーザーが空間マッピングで寝室を「視界外＝不在リファレンス」として使用したことで確認）。旧 worklog の設置前提は更新されている。

## 1. 症状（ユーザー報告）

「センサーの 1m 前に座っているのに在室反応されない。この状態でも検知してほしい。」

着座直後の実測（gateway `GET /control/presence`）:

```
presence=-10  pres_flag=false  object_raw=-8060  ambient=30.89℃  → present=false
last_seen_s_ago=873.9   state=active   absent_after_s=1080
```

→ 14 分以上「未検知」のまま、18 分デバウンスだけで辛うじて active。あと 3 分で目の前にいるのに absent へ倒れる寸前だった。

## 2. 原因

TMOS（STHS34PF80）は**熱式**。`read_tmos` は埋め込みアルゴリズムの `presence`（レジスタ 0x3A）を読み、`present = pres_flag or presence > 200` で在室判定していた。

- この埋め込み presence は**「動くもの」に最適化**されており、**静止した体を ~1 分で背景吸収**して 0 付近へ減衰する（PIR 同様の弱点）。
- 一方、生サーモパイル `object_raw`（TOBJECT, 0x26）は**静止した体の暖かさを保持し続けている**——ただし在室判定には使われていなかった。

## 3. 計測（空間マッピング）

行き当たりばったりを避け、ユーザーが部屋の各地点に ~35 秒ずつ静止し、全 TMOS 値を連続ログ（`scratchpad/spatial_capture.jsonl`）→ 地点ごとに分布を突合。**同時刻の空室基準からの `object_raw` 超過 Δ**:

| 地点 | object_raw | 室温 | Δ(空室比) | 静止検知 |
|---|---|---|---|---|
| 自分の席 1m（本命） | -8260 | 31.5 | **+745** | ◎ |
| 恵梨子さん席（テーブル） | -8512 | 31.4 | +290 | ○ |
| 立ち | -8884 | 31.6 | +260 | ○ |
| キッチン | -8852 | 31.5 | +134 | △ |
| ソファ | -8890 | 31.5 | +29 | ✗ 死角 |
| 空室（寝室/廊下/終了後） | -8970〜-9043 | 31.5 | 0（基準） | — |

- 空室ノイズの sd ≈ ±35。Δ が 100 以上あれば余裕で分離。
- **計測中に室温 30.9→31.6℃ 上昇 → 空室 object_raw が -8697→-9043（約 -510/℃）連動**。＝**固定しきい値は不可、適応ベースライン必須**を実データで確定。
- ソファは Δ+29＝空室同然＝センサーの視野/距離の死角（部屋スケールは元々 ToF 待ちの領域）。

## 4. 設計

`gateway/stackchan_mcp/presence.py` の `PresenceMonitor` に `_update_occupancy(snap)` を新設し、`_poll_once` の占有判定をここへ集約。

```
occupied = moving(presence>200 or pres_flag)          ← 従来（入室・身じろぎ）
        OR (armed AND object_raw − baseline > MARGIN)  ← 新規（静止した体を保持）
```

- **適応ベースライン**: 空室時の `object_raw` を追従する基準値。
- **アーミング**: 本物の `moving` 検知があった時だけ static 判定を有効化 → 緩く温まる壁/家電を誤ラッチしない。
- **ヒステリシス**: `object_raw − baseline ≤ DISARM_MARGIN(60)` で disarm（離脱検知）。

### 4.1 設計の山場（履歴 replay で凍結バグを発見）

当初は「在室中はベースラインを凍結（静止体を吸収しないため）」とした。これを**実機ログ 9.7 日分（162k サンプル）に replay** したところ:

| 指標 | 凍結案 | 非対称追従（採用） |
|---|---|---|
| static_present 点灯率 | 53% | **15.4%** |
| 純増 occ（埋め込み超過分） | 31.7% | **6.3%** |
| 最長 static run | **2.6 日** 🔴 | **75.5 分** |
| run ≥ 120 分 | 多数 | **0 件** |

凍結案は、**凍結した基準が日内の室温ドリフトに追従できず**、`object_raw` が永久に「基準+150」超のまま張り付いて 2.6 日連続ラッチした。

→ **凍結を廃止し、非対称 EMA 常時追従**へ:
- `object_raw` が**下がる**（人が去る/室温で空室値が下降）→ **速い**（`ALPHA_DOWN=0.08`, τ≈60s）→ 離脱を即検知
- `object_raw` が**上がる**（人が来た）→ **遅い**（`ALPHA_UP=0.004`, τ≈40分）→ 静止者を保持しつつ、永久ラッチは τ で自然に解ける

この単一の τ_up が「静止保持時間 ↔ 誤ラッチ持続時間」のトレードオフそのもの。

### 4.2 定数（presence.py 上部）

```python
OBJ_PRESENT_MARGIN = 150       # 静止在室と判定する超過（空室sd ≈35 の ~4倍）
OBJ_DISARM_MARGIN  = 60        # ヒステリシス下限
OBJ_BASELINE_ALPHA_DOWN = 0.08 # 下げ追従（速い・離脱復帰 ~60s）
OBJ_BASELINE_ALPHA_UP   = 0.004# 上げ追従（遅い・保持 ~40分・反ラッチ）
```

観測用に `snapshot()` と presence ログ各行へ `obj_baseline / obj_armed / static_present` を追加（実機でのチューニング根拠を残す）。

## 用語

- **TMOS / STHS34PF80**: 熱式（サーモパイル）人感センサー。PaHUB2 mux ch3 @0x5A。`presence`=埋め込みアルゴリズム出力（動体最適・静止は減衰）、`object_raw`=生サーモパイル（静止体を保持・室温で DC ドリフト）。
- **適応ベースライン / 背景差分**: 「空室の基準値」を動的に推定し、現在値の超過分で前景（人）を検出する古典的手法。本件は室温ドリフトに追従させるために必須。
- **非対称 EMA**: 上げと下げで平滑化係数を変える指数移動平均。本件は「下げ速・上げ遅」で『離脱は即・静止は保持・永久ラッチ防止』を両立。
- **アーミング**: 本物の動体検知があった時だけ静止判定を有効化するゲート。動体を伴わない熱源（壁/家電）の誤ラッチを防ぐ。
- **デバウンス（absent_after_s）**: 占有信号が途切れてから ABSENT に倒すまでの待ち（1080s）。非対称ヒステリシスの「退室タイマ」。static 保持の谷を埋める二重の安全網。
