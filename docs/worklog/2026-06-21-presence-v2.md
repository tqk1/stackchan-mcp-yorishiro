# 在室判定エンジン v2 — 就寝ラッチ＋退室窓拡張（Phase 1）

日付: 2026-06-21
ブランチ: feature/multiturn（presence-log 基盤の上に積む）
関連プラン: `~/.claude/plans/encapsulated-imagining-donut.md`

## 作業概要（なぜ・なにを）

ケンジさんの要望「センサーの蓄積データから正確に在室ステータスを把握できる仕組みを構築したい」を受け、在室判定（TMOS 熱式PIR）を作り変えた。3.2日分(54,735サンプル)の実ログ `~/.stackchan/presence_log.jsonl` を集計し、設計の制約を確定させてから実装した。

### データが証明した最重要の制約

**TMOS 単独では「静止した在室者」と「外出（空室）」を区別できない。**
- 在室中の離席(<20min)と外出(>20min)で presence 生値分布がほぼ完全に重なる（両方 max 48〜191）。空室でも熱ノイズ・窓外・気流で presence は時々跳ねる。
- → presence 生値・移動窓・分散のどれでも分離不可。「連続データを賢く処理すれば分かる」はこのセンサーでは原理的に不成立。
- → **時刻スケジュール × センサーのハイブリッドが唯一の現実解**。

### 補助事実
- pres_flag（センサー内蔵閾値判定）は信頼できる（True で presence med=1058 / False で med=0・p90=22、50倍分離）。
- 室温ドリフトは軽微（無人時 p90=16〜48 @27-36℃）→ 自動較正の実益は小さい。
- 在室「present区間内」の谷間は最大444秒。
- 物トラブル日(6-20)を除けば睡眠帯(22:00-06:30)に毎晩必ず断片的には在室を拾える（6-18夜=断片的/6-19夜=8.5h連続100%）。

## 実装（Phase 1）

対象: `gateway/stackchan_mcp/presence.py`（＋テスト `tests/test_presence.py`）

### 1. 就寝ラッチ `_asleep`
睡眠帯に一度でも在室確認したら、検知が途切れても覚醒帯まで QUIET を維持する。TMOS は「動く人」しか見えず、静止就寝は原理的に検知不能なため、時刻スケジュールで補う。
- `_update_sleep_latch()`（副作用・poll でのみ更新）: 覚醒帯でクリア／睡眠帯で `_occupied()` が True ならセット（None/False は falsy → 立たない＝外泊は睡眠帯で在室未確認なのでラッチが立たず ABSENT のまま → **就寝と外泊を区別**）。
- `_derive_state()`（純粋導出）: occ False でも `quiet_now and self._asleep` なら QUIET。
- `_poll_once()`: `_last_present_mono` 更新の直後・`_derive_state()` の直前に `_update_sleep_latch()` を挿入。
- `snapshot()` と presence ログに `asleep` を露出（QUIET の内訳＝就寝中 vs 覚醒帯在室を区別）。

### 2. 退室窓の拡張 450→1080秒（18分）
覚醒帯の誤ABSENT（在室なのに静止・範囲端で検知が途切れて absent に落ちる）対策。`~/.stackchan/presence_state.json` の `absent_after_s` を 1080 に更新。
- 根拠: 在室中の最大谷間444秒の2.4倍マージン。真の外出は1200秒超ギャップに集中＝20分手前で区別。
- トレードオフ: 外出後最大18分は「在室」を保持（heartbeat は fail-open・gesture=off で実害小）。ダッシュボードで実行時調整可。

### 設計判断: `exit_after_s` の新設を却下し `absent_after_s` を再利用
当初プランは「非対称ヒステリシス」のため新パラメータ `exit_after_s` を導入する案だった。しかし**現状の `_occupied()` は既に「入りは即時（present 観測で `_last_present_mono` 即更新）・出は `absent_after_s` でデバウンス」という非対称構造**で、`absent_after_s` がまさに退室タイマーそのもの。並行パラメータの新設は同概念の二重化（過剰設計）。
- 再利用により: **http_server 変更ゼロ・既存テスト22本ゼロ改修・移行ロジック不要**。外部挙動は同一。
- 「非対称ヒステリシス v2」の実体 = 退室窓の値を 450→1080 に上げる ＋ 就寝ラッチ。

## 構成図（状態遷移 v2）

```
        present観測（即 _last_present_mono 更新 = 入りは速い）
 UNKNOWN ──────────────────────────────────────► 在室
   ▲  (起動/sensor fault/no device = fail-open)    │ ACTIVE(覚醒帯) / QUIET(睡眠帯)
   │                                                │ absent_after_s(1080s) 無検知 = 出は遅い
   │                                                ▼
   └──────────────────────────────────────────── ABSENT
       睡眠帯で _asleep が立っていれば QUIET 維持（就寝・検知切れを橋渡し）
```

## 用語

- **TMOS**: STHS34PF80。熱式PIR。動く熱源（人）を検知。静止体は見えない。PaHUB2 mux ch3 経由・I2C 0x5A。
- **pres_flag**: TMOS 内蔵の在室判定フラグ（閾値処理済み・信頼できる主信号）。
- **debounce（absent_after_s）**: 在室を失ってから ABSENT を宣言するまでの猶予＝退室タイマー。
- **fail-open**: 確信を持って ABSENT のときだけ heartbeat を止める。UNKNOWN/QUIET は許可（センサー故障で無言にしない）。
- **就寝ラッチ**: 睡眠帯の在室確認を記憶し、静止就寝の検知切れを覚醒帯まで橋渡しする状態。
