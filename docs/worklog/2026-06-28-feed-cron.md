# worklog 2026-06-28 — フィードに深夜の Obsidian 整理 cron を表示

## 1. 概要（何をしたか）

ダッシュボード（<https://razer-server.tailc0a7ab.ts.net> → 📜 フィードタブ）に、
**深夜に走る Obsidian Vault 整理系 cron の「最終実行」** を表示できるようにした。
一方で **Claude Code のトークン確認 cron（毎時 `fetch_usage.py`）は引き続き非表示**。

### なぜ（経緯）

- 前日 2026-06-27 のフィード実装（commit `4bf0336`）では、当初「毎時 `fetch_usage.py`
  （CC トークン使用率）」をフィードに載せたが、**毎時エントリがフィードを占有し、
  サーバータブの CC 利用率とも重複する**ため、ケンジ判断で cron を**完全除外**した
  （worklog `2026-06-27-activity-feed.md` 冒頭の追記）。
- 今回はその「逆向き」の調整。トークン cron は不要なまま、深夜の Obsidian 整理 cron
  （1〜5 時台・実体のある housekeeping）は「ちゃんと走ったか」を見たい、という要望。

### 方式（ケンジ選択：ログ読み取り方式）

gateway が各ジョブの `/tmp/<job>.log` の **mtime（最終更新時刻）= 最終実行時刻** を読み、
ジョブごとに 1 件の feed item（`source="cron"`）を生成する。
**crontab も Obsidian スクリプトも一切触らない**（自己完結・本リポジトリ内のみ）。
`fetch_usage.log` を対象リストに入れない＝自動的に非表示。

> 構造化記録方式（crontab をラッパー経由にして実行履歴を JSONL 追記）は、変更範囲が
> 本プロジェクト外（crontab）に広がるため不採用。タイムスタンプは mtime が確実なので、
> ログ読み取りでも十分堅牢と判断。

## 2. データの流れ

```
[deep-night cron] build_moc.py / notes-tidy.sh / inbox-drain.sh ...（8本）
      │ 実行のたびに追記
      ▼
  /tmp/<job>.log   ← mtime = 最終実行時刻 / 末尾行 = 直近の結果
      │
      │ gateway が stat + tail（read-only, best-effort）
      ▼
[gateway] GET /control/activity ──┬─ activity_log.jsonl（自律行動）
  _gather_activity()              ├─ _read_cron_runs()    ← 今回追加
                                  └─ presence_reports/*.json（日次レポート）
      │ ts_unix 降順マージ → cap
      ▼
[status_api :8080] /control/activity を素通しプロキシ
      ▼
[dashboard.html] 📜 フィードタブ：⏱️ 整理 フィルタで cron だけ抽出も可
```

## 3. 変更点

### gateway（`stackchan_mcp/http_server.py`）

- `CRON_JOBS`: Obsidian 整理 cron 8 本の `(ログパス, ラベル)` を定義。
  **トークン cron（`fetch_usage.log`）は意図的に含めない**（コメントで明記）。
  - `inbox-drain`→Inbox 整理 / `build_moc`→MOC 構築 / `build_notes_review`→ノートレビュー更新 /
    `weekly-digest`→週次ダイジェスト / `notes-tidy`→ノート整理 /
    `notes-tidy-suggest`→整理提案 / `articles-recommend`→記事レコメンド /
    `self-reflect`→自己ふりかえり
- `_last_log_line(path)`: ファイル末尾 4KB だけ読んで最後の非空行を返す（≤200 文字）。
- `_read_cron_runs(jobs=None)`: 各ジョブの `stat().st_mtime`→`ts_unix`、末尾行→`text`、
  末尾行にエラーマーカー（`error` / `traceback` / `permission denied` ...）があれば
  `status="error"`。ログ欠損（再起動で `/tmp` が消える等）はそのジョブを skip。
  `jobs=None` のとき**呼び出し時に**モジュール変数 `CRON_JOBS` を参照（テスト差し替え用）。
- `_gather_activity()`: `source is None or source == "cron"` のとき cron をマージ。

### dashboard（`~/razer-dashboard/dashboard.html`、非 git）

- `⏱️ 整理` フィルタボタン追加 / `FEED_GROUP.cron = ['cron']`。
- `feedIcon` に cron→`⏱️`、`feedTitle` に cron→ジョブ名（subtype）。
- ctl-note 文言を「毎時 cron」→「深夜の Obsidian 整理 cron」に更新。

### tests（`tests/test_activity_feed.py`）

- `_read_cron_runs`: mtime/末尾行/error 検出/欠損 skip を検証。
- `_gather_activity`: cron が source=None で混ざる・`source="cron"` で絞れる、を検証。
- 既存の merge テストが**実機の `/tmp/*.log` を拾って壊れない**よう、`_setup_sources` で
  `monkeypatch.setattr(http_server, "CRON_JOBS", ())` して中和。

## 7. 用語

- **cron**: 定時実行のスケジューラ。ここでは毎日深夜 1〜5 時台に Obsidian Vault を
  自動整理するジョブ群（MOC 構築・Inbox 整理・ノート整理 等）。
- **mtime**: ファイルの最終更新時刻。ログは実行のたびに追記されるので、mtime ≒ 最終実行時刻。
- **feed item の source**: `heartbeat`/`proactive`/`presence`/`home`（JSONL 由来）＋
  `report`（日次レポート）＋ **`cron`（今回追加・/tmp ログ由来）**。
